# 在一台手机上验证网关

这份手册给执行测试的 agent 和它身边的人用。分四级，一级比一级要求的条件多。每一级做完都用 `tools/evidence.py` 取证并校验，结果是能给别人看的证据，不是“我觉得可以”。

开始前先读 [AGENTS.md](../AGENTS.md) 里的规矩。

| 级别 | 证明了什么 | 需要什么 |
| --- | --- | --- |
| L0 | 代码能编译，单元测试通过 | 一台电脑 |
| L1 | 这款手机能运行网关：装得上，权限和默认应用设得了，音频服务起得来，送话通道打得开 | 手机、数据线、SIM 卡、手机的主人在场 |
| L2 | 电话和短信真的能经它走，两边都听得见 | 另加：配对好的 iPhone，另一部能打电话的手机，两个人（或一个人拿两部手机） |
| L3 | 放着不管也不掉线 | 另加：时间 |

只做到 L1 也有用：它回答了“这款手机有没有戏”。很多手机在 L1 的第 4 步就能看出结果。

## 准备

- 电脑上有 `adb`（Android SDK 的 platform-tools）和 Python 3。
- 手机：Android 10 及以上，arm64，插着能打电话的 SIM 卡，连着 Wi-Fi，开了开发者选项里的“USB 调试”，用数据线连电脑，并在手机上点过“允许 USB 调试”。
- 手机的主人在旁边。安装确认、权限弹窗、厂商的各种确认都要他来点。

确认连上了，记下序列号，后面所有命令都带上它：

```bash
adb devices
```

下面用 `$S` 代表这台手机的序列号。

## L0：编译和单元测试

只在你改了代码时需要。按 [README.md](../README.md) 的“编译”一节，然后：

```bash
./gradlew :gateway:testDebugUnitTest :gateway:assembleDebug
```

全部通过才往下走。

## L1：这款手机能不能运行网关

### 1. 装上

没改代码就用官方安装包：到本仓库 Releases（GitHub 或 Gitee 镜像）下载 `simnest-gateway-<版本>-<编号>.apk`，按发布说明里的 SHA-256 核对：

```bash
shasum -a 256 simnest-gateway-*.apk
```

```bash
adb -s $S install simnest-gateway-*.apk
```

有的手机（小米等）会在屏幕上弹安装确认并倒计时，请主人点“继续安装”。返回 `INSTALL_FAILED_USER_RESTRICTED` 就是没人点或超时了，再装一次。华为可能要求在开发者选项里打开“仅充电模式下允许 ADB 调试”。

### 2. 不做任何设置，先探一下音频

这一步最快给出结论，也不需要 iPhone。它从电脑直接启动音频服务，看这款手机让不让 shell 打开通话的送话通道：

```bash
tools/start-bridge.sh $S
```

看输出的最后几行：

| 看到 | 意思 |
| --- | --- |
| `bridge ready port=47710 …` 后面跟着 `tx warmed` | 好。音频服务以 shell 身份起来了，送话通道打得开 |
| `tx warm failed … TX_ROUTE_UNAVAILABLE` | 系统没有把“通话送话”这个输出设备列出来。见 ADAPTING 的“送话通道” |
| `tx warm failed … TX_ROUTE_REJECTED` | 设备有，但不让音轨指定它。同上 |
| 没有 `bridge ready`，只有 Java 报错 | 音频服务本身没起来。把报错的前几行记下来，见 ADAPTING 的“音频服务起不来” |

开头那一大段 `FileNotFoundException … theme_compatibility.xml` 的报错是小米系统自己的，和结果无关。

这一步通过，只说明“写得进去”，不说明对方听得见，也还没试“录得到对方”。那两件事要到 L2 的真实通话里才知道。

### 3. 在手机上走一遍引导

请主人打开“SimNest 网关”，同意条款。没配对时首页下方有“先准备这台手机”，照着做：

1. 点“允许网关所需权限”，弹窗都选允许。
2. 设为默认短信应用、默认电话应用。
3. “设置音频服务”里按顺序做。有无线调试的手机：打开开发者选项和无线调试，按提示配对一次。没有无线调试的手机（华为的 HarmonyOS 等）：点“没有‘无线调试’？”，然后在电脑上执行 `adb -s $S tcpip 5555`，回手机点“连接并允许”，在弹出的“是否允许 USB 调试”里勾“始终允许”。
4. 引导里和厂商有关的几步（自启动、省电策略、应用启动管理）照做。这几步系统不让应用读结果，网关没法替你确认，漏了的后果是熄屏后掉线。

你可以读屏幕上的字来给主人指路，不要替他点：

```bash
adb -s $S shell "uiautomator dump /sdcard/ui.xml >/dev/null; cat /sdcard/ui.xml" | tr '>' '\n' | grep -o 'text="[^"]*"' | grep -v '""'
```

引导里某一步在这款手机上找不到对应的系统页面、或者文字对不上，记下来：这正是适配要改的地方。

### 4. 取证并校验

```bash
tools/evidence.py collect evidence/<厂商>-<型号>-android<版本>/<网关版本> --serial $S
```

```bash
tools/evidence.py check evidence/<厂商>-<型号>-android<版本>/<网关版本>
```

目录名用小写和连字符，例如 `evidence/xiaomi-21091116ac-android13/0.43.0`。在生成的 `report.md` 里填上测试者和网关版本，勾上 L1 里真的做了的项。

**取证要趁早。** 音频服务的日志在它每次启动时清空：重启手机、重装或更新网关、网关自己重启音频服务之后，之前那些通话的记录就没了。打完测试电话先 `collect`，再做别的。

`check` 会逐项打印 PASS 或 FAIL，最后一行是“这份证据达到了哪一级”。没配对时“网关服务在前台”“网关连上了音频服务”两项是 n/a，不算失败。

## L2：电话和短信

需要：这台网关和一台 iPhone 配好对；另一部手机（下面叫“对方手机”）用来打进打出；主人当场告诉你网关这张卡的号码和对方手机的号码。**号码只用他现在说的。**

### 1. 配对并开启

主人在网关上点“出码配对”，用 iPhone 上的 SimNest 扫码，两边数字一致后确认，再点“开启网关”。配对后网关首页变成状态页。

### 2. 网关自检

网关首页点“自检”，点“开始自检”。逐项看，尤其是：

- “语音通道”要是“音频服务在运行”。
- “SIM 卡”要有服务。
- “后台保活和权限”：如果写着系统冻结过网关，先按提示处理，否则后面的通话测试会时好时坏。

把自检页面上的文字记进 `report.md` 的 Notes（用上面读屏幕的命令）。

### 3. 打进来

先确认两台手机都空闲（0 空闲，1 响铃，2 通话中）：

```bash
adb -s $S shell dumpsys telephony.registry | grep -m1 mCallState
```

请主人用对方手机拨网关的号码；或者对方手机也连着电脑、主人同意的话由你拨：

```bash
adb -s <对方手机> shell am start -a android.intent.action.CALL -d tel:<主人刚说的网关号码>
```

拨出后 10 秒内再看一次网关手机的通话状态，应该变成 1。没变就挂断，停下来问：号码对不对、卡有没有服务。

主人在 iPhone 上接听。**通话至少 90 秒**，两边各说一句能核对的话，例如一边报今天的日期，一边报手机型号。同时请主人留意三件事，这是日志证明不了、只能靠人的：

- 对方手机里听得清 iPhone 这边说话吗？
- iPhone 里听得清对方手机那边说话吗？
- 网关手机自己有没有出声（听筒、扬声器都应该是静的）？

通话中可以看着音频服务的日志：

```bash
adb -s $S shell tail -n 5 /data/local/tmp/cloudsim-bridge.log
```

正常时每隔几秒一行 `state ice=CONNECTED members=1 uplink=…/…/…`，三个数字是“帧数/不是静音的帧数/最大音量”，前两个数都在涨。

挂断后日志里会有一行总结：

```
session 44e87421 ended stopped injected=19173 dropped=0 downlink=19102/17943/27916 uplink=19179/19095/23384 …
```

| 字段 | 意思 | 正常的样子 |
| --- | --- | --- |
| `downlink=帧数/非静音帧数/峰值` | 从通话里录到的对方声音，发给 iPhone | 非静音帧占多数，峰值几千以上 |
| `uplink=帧数/非静音帧数/峰值` | 从 iPhone 收到、写进通话送话通道的声音 | 同上 |
| `injected` `dropped` | 写进送话通道的块数和丢掉的块数 | 丢掉的不到 1% |
| `ended` 后面的词 | 结束原因 | `stopped` 是正常挂断 |

一帧 20 毫秒，帧数乘以 0.02 就是秒数。

`downlink` 的非静音帧几乎是 0：这款手机上录不到对方的声音。`uplink` 数字正常但对方说听不见：声音写进去了却没到对方那里。这两种情况都见 ADAPTING。

### 4. 打出去

主人在 iPhone 的 SimNest 里选这张卡，拨对方手机的号码，对方接听，同样至少 90 秒、同样三件事。

### 5. 短信

- 对方手机发一条短信到网关的号码，iPhone 上收到。
- iPhone 经这张卡发一条给对方手机，对方收到。

### 6. 取证并校验

再跑一遍 `collect` 和 `check`（同一个目录，日志会更新，`report.md` 不会被覆盖）。在 `report.md` 里勾上 L2 里做到的项。

`check` 对 L2 的要求：日志里至少两通超过一分钟、两个方向都有声音、丢帧不到 1% 的通话；`report.md` 里勾了“对方听到了”“iPhone 听到了”“网关手机没出声”和短信两项。前者是机器看的，后者是人说的，两样都要。

## L3：放着不管

- **熄屏 30 分钟**：拔掉数据线（有的系统充电时不限制后台，插着电测不出问题），熄屏放 30 分钟，然后从对方手机打进来，iPhone 应该照常响。之后在网关自检里看“后台保活和权限”有没有报冻结。
- **重启**：重启网关手机，解锁一次，不打开网关应用，等两分钟，打进来，iPhone 应该照常响。没有无线调试、靠 `adb tcpip` 的手机重启后调试端口会关，音频服务起不来，这是已知限制：要重新连电脑执行一次。把实际情况写进报告。
- **24 小时**：开始和结束各打一通，都正常。

做到的项在 `report.md` 里勾上，再 `check` 一次。

## 交结果

`evidence/<机型>/<版本>/` 整个目录就是结果。怎么提交、别人怎么验收，见 [CONTRIBUTING.md](../CONTRIBUTING.md)。即使结论是“这款手机不行”，也请提交：L1 第 2 步的输出和 `device.txt` 能帮下一个人少走弯路。

测完请收尾：测试装的包主人不想留就卸掉；用 `adb tcpip 5555` 开过的调试端口，不用了就重启手机关掉。
